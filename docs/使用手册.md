# 充电结束提醒 使用手册

电瓶车在扫码充电桩上充电，人不在旁边，最怕的是没充满就被人拔掉。这个工具每隔几分钟读一次你自己的充电订单，订单结束时按"实际充了多久"对比"本该充多久"，把结论推到你微信。

结论先说：整套东西跑在 GitHub Actions 上，你的电脑和手机都不需要在场；只需要一次性拿到属于你自己的 `openid`，填进仓库密钥，之后不用管。

## 它如何判断"被拔了"

平台给的两个字段就够用：进行中订单的 `Sysc`（剩余分钟），已结束订单的 `UseTimes`（实际使用分钟）。

计划时长取最后一次观测到的"已过分钟 + 剩余分钟"，订单结束后看 `UseTimes` 与它的差：

| 情况 | 判定 | 推送标题 |
| --- | --- | --- |
| `UseTimes` 比计划少 5 分钟以上 | 提前断电，多半是被拔或充满停机 | `⚡ 充电提前结束（可能被拔）` |
| `UseTimes` 接近计划 | 时间用满，正常结束 | `✅ 充电结束（时间用满）` |

订单从「进行中」列表消失、但平台历史表还没更新时，程序等 15 分钟；仍查不到就按最后观测的剩余分钟判定，避免漏报。同一订单只提醒一次。

## 你需要的准备

- 一个 GitHub 账号（Actions 在公共仓库上不花额度）。
- 能取出自己 `openid` 的手机或电脑。
- 一个推送通道的 key，见[第三步](#第三步选推送通道)。
- 可选的本地 Python 3.10+，用来试跑。

本项目只适用于 `semiot.wasion.cn`（威胜智能充电平台）这一套系统。换别的平台要改 `semiot.py` 里的接口。

## 第一步：拿到自己的 openid

`openid` 是微信对某个公众号给你的固定编号，对同一个充电平台永远不变，拿到一次可以一直用。它出现在订单接口的 URL 里，所以最直接的办法是在手机微信里打开订单页时抓一次包。

1. 手机装抓包工具：iOS 用 [Stream](https://apps.apple.com/app/id1312141691)，Android 或 Windows 用 [Reqable](https://reqable.com)。两者都是免费可用的。
2. 在工具里「开始抓包」，并按它的引导安装并**信任** HTTPS 证书。iOS 必须在「设置 > 通用 > 关于本机 > 证书信任设置」里手动打开信任开关，只装描述文件不生效，这是最容易漏的一步。
3. 用微信扫描充电桩上的二维码，进入订单页，点开「我的订单」。页面会加载「进行中」和「已结束」两张表。
4. 回到抓包工具，筛选域名 `semiot.wasion.cn`，找一条请求路径是 `/PersonnelOrder/GetInOrders` 或 `/PersonnelOrder/GetHisOrders` 的记录，它的 URL 形如：

   ```
   https://semiot.wasion.cn/PersonnelOrder/GetInOrders?start=1&end=5&openid=oABCDEFG1234567890abcdefghijk
   ```

   `openid=` 后面那串就是你要的值，长度通常在 28 位左右。

5. 记录里只看 URL 就够，不需要 Cookie，也没有 token 会过期。

抓不到 `/PersonnelOrder/*` 的请求，通常是证书没被真正信任，表现为抓包里只有一堆 `CONNECT` 隧道记录、没有明文的请求头和响应。回到第 2 步重新确认信任开关。

## 第二步：本机试跑

先确认接口对你的账号有效，再去折腾部署。

```bash
git clone https://github.com/<你的用户名>/charger-alert.git
cd charger-alert
pip install requests

cp config.example.json config.json
# 编辑 config.json，把 openid 填进去，push.token 先留空
python monitor.py --once --dry
```

`--dry` 只打印不推送。看到类似输出就说明连接正常：

```
[21:03:11] 进行中 1 单：153540576120261101000000000 | 跟踪中 1 | 已结束累计 0
```

`进行中 0 单` 也正常，说明当前没有正在充的电。接口不通会打印 HTTP 状态码和错误。

## 第三步：选推送通道

推送通道由两个环境变量或 `config.json` 里的字段决定，换通道不用改代码。

| channel | token 是什么 | 怎么拿 | 送到哪 |
| --- | --- | --- | --- |
| `serverchan` | SendKey，形如 `SCT123456T...` | [sct.ftqq.com](https://sct.ftqq.com) 微信扫码 | 微信，服务号「方糖」 |
| `pushplus` | token | [pushplus.plus](https://pushplus.plus) 微信扫码 | 微信，服务号「pushplus」 |
| `ntfy` | 自己起的 topic 名 | 手机装 ntfy App，订阅同名 topic | ntfy App 通知，免注册 |
| `bark` | Bark key | iPhone 装 Bark App | Bark 通知 |

微信通道每天有免费条数限制（Server酱免费版 5 条/天）。一次充电只占 2 条：开始 1 条、结束 1 条。想省额度，把 `config.json` 里的 `notify_start` 改成 `false`，只在结束时提醒。

填好之后先自检一次，别等真充电时才发现通道不通：

```bash
PUSH_CHANNEL=serverchan PUSH_TOKEN=你的SendKey python monitor.py --test-push
```

Windows PowerShell 里这样写：

```powershell
$env:PUSH_CHANNEL='serverchan'; $env:PUSH_TOKEN='SCT...'; python monitor.py --test-push
```

手机收到消息即通道可用。

## 第四步：部署到 GitHub Actions

目标是让它 7×24 跑，而你的设备不用开机。

1. 在 GitHub 新建一个仓库，把本项目推上去。想让 Actions 不消耗额度就设成 public，本仓库代码里不含任何密钥。
2. 打开仓库的 `Settings > Secrets and variables > Actions`，添加三个 secret：

   | 名称 | 值 |
   | --- | --- |
   | `SEMIOT_OPENID` | 第一步拿到的 openid |
   | `PUSH_CHANNEL` | `serverchan` / `pushplus` / `ntfy` / `bark` |
   | `PUSH_TOKEN` | 对应通道的 key |

3. 打开 `Actions` 标签，选择 `charger-alert`，点 `Run workflow` 跑一次，看日志里是否出现 `进行中 N 单`。第一轮成功即部署完成。

工作流 `.github/workflows/monitor.yml` 的行为：

- 单次运行执行 `monitor.py --loop 300 --minutes 320`，即每 5 分钟查一次、最长跑 5 小时 20 分。
- 每轮结束前用内置 `GITHUB_TOKEN`（需要 `actions: write` 权限）触发下一轮，形成连续轮询。
- `state.json` 通过 Actions 缓存跨轮次传递，保证同一订单不重复提醒。
- `schedule` 触发器保留着做备用。GitHub 的 cron 在部分仓库长期不触发，所以主力是上面的自续链。

## 第五步：日常运维

**看它是否在跑**：`Actions` 标签下应有 `charger-alert` 的运行记录，状态 `in_progress` 表示正在轮询，日志里每 5 分钟出一行 `进行中 N 单`。

**暂停**：

```bash
gh workflow disable charger-alert --repo <你的用户名>/charger-alert
```

当前这轮跑完就不再续接（最长等 5 小时 20 分）。恢复用 `gh workflow enable`。

**改检查间隔**：改 `monitor.yml` 里 `--loop` 的秒数和 `--minutes` 的分钟数。间隔越短，"被拔"到收到提醒的延迟越小，请求也越多，5 分钟对家用充电来说足够。

**清理历史状态**：删掉仓库 Actions 缓存里 `state-` 开头的条目即可，程序会重新开始跟踪。

## 常见问题

**收不到提醒。** 先跑 `python monitor.py --test-push`。通道通但还是收不到，检查微信里是否关注了对应服务号（方糖或 pushplus），以及当天免费条数是否用完。

**`进行中` 一直是 0 单，但手机上明明在充。** 确认订单是否属于这个 openid。换过微信账号、或用别人的手机扫码下单，订单就记在别人名下。

**openid 会失效吗。** 不会。它对同一个公众号固定不变。只有换微信账号、或平台换公众号时才会变。

**提醒延迟多久。** 平台接口本身秒级响应，延迟来自轮询间隔（5 分钟）与 GitHub 的排队时间（几分钟之内）。订单结束到推送，通常 5 到 10 分钟。

**历史表还没更新就推了提醒。** 这是有意的兜底：订单从进行中消失 15 分钟仍查不到记录时，按最后观测的剩余时间判定，标题里会注明"平台历史表暂未更新"。

**Actions 显示超时或长时间排队。** 公共仓库的免费 runner 有排队，等待属正常。自续链在上一轮结束时不依赖排队顺序，只会晚开始，不会中断。

**long-running 会不会违反 GitHub 政策。** 每个仓库一个 job、每 5 分钟一次 HTTP 请求，属于定时任务范畴。若担心，把 `--minutes` 调小到 60、`--loop` 调到 600，占用更低但提醒更慢。

## 隐私与安全

这个工具会让人看到你的充电记录，所以密钥不能进仓库：

- `openid`、SendKey、topic 名只放在 GitHub Secrets 或本地 `config.json`，`.gitignore` 已排除 `config.json`、`state.json`。
- 不要在 issue、截图、日志里贴这些值。日志里它们会被 Actions 自动打码成 `***`。
- 不要使用别人的 openid。那等于读取他人账户的充电记录。
- 请求频率保持在几分钟一次。高频轮询对平台不友好，也容易被限流。

## 接口附录

平台是 ASP.NET MVC 应用，订单接口用 URL 参数里的 `openid` 做身份，不校验 Cookie 或微信授权。以下均为实测结果。

```
POST https://semiot.wasion.cn/PersonnelOrder/GetInOrders?start=1&end=10&openid=<openid>
POST https://semiot.wasion.cn/PersonnelOrder/GetHisOrders?start=1&end=10&openid=<openid>
```

`start` 与 `end` 都从 1 开始且包含端点，每页最多 10 条。响应结构：

```json
{"success": 1, "message": "", "data": [
  {"DeviceNumber": "120000000012", "PaymentTime": "2026-11-22 14:41:17",
   "Sysc": 608, "OrderNo": "153540576120261101000000000",
   "PayType": "免支付", "PayAmount": 0.0,
   "UseTimes": 135, "CostElectricit": 0.39}
]}
```

| 字段 | 含义 |
| --- | --- |
| `OrderNo` | 订单号，程序用它去重 |
| `DeviceNumber` | 充电桩编号 |
| `PaymentTime` | 订单开始时间（服务器为 UTC，接口返回值为本地时间） |
| `Sysc` | 进行中订单的剩余分钟 |
| `UseTimes` | 已结束订单的实际使用分钟 |
| `CostElectricit` | 充入度数 |

`/PersonnelOrder/GetOrderList` 是空壳接口，任何参数都返回空数组，不要使用。
